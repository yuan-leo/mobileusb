# MobileUSB v2.1.0 - browser USB controls and drag-and-drop

## Changes

- Add a live USB status panel showing how MobileUSB should appear to the target.
- Show live UDC state, negotiated speed, gadget function, backing image, queued changes and last sync.
- Add **Force disconnect** to simulate USB removal. It requires explicit confirmation that the target is idle/ejected.
- Add **Force present** to reconnect the existing mass-storage image without silently synchronizing queued web changes.
- Keep USB control requests queue-based so the browser remains unprivileged; the root controller performs the actual gadget operations.
- Add drag-and-drop multi-file selection while preserving the existing upload staging, FAT32 filename checks, locking, collision behavior and atomic moves.
- Fix the status wording so queued web changes do not imply that a physically unattached USB host is "waiting for eject."
- Add CI coverage for the new browser and controller paths.

## Safety

Force disconnect is intentionally dangerous if the target is still reading or writing. It is equivalent to pulling a USB drive and may lose buffered target writes or damage FAT state. Use it only when the printer/host is idle and no longer using the drive.

Force present does not copy queued browser changes into the USB image. Use the normal acknowledged synchronization flow when you need pending files published to the target.

## Deployment

This release updates the repository and installer package only. It does not automatically modify an already-running Raspberry Pi. Use the normal upgrade procedure after ejecting/unmounting the target drive.

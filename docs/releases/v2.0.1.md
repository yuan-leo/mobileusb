# MobileUSB v2.0.1 - atomic web storage fix

Fixes `[Errno 18] Invalid cross-device link` when the web manager moves completed
uploads from `.upload-tmp` into `incoming`. The previous systemd sandbox created
separate writable bind mounts for sibling directories, so Linux rejected atomic
renames even on the same physical filesystem. Trash, restore and text replacement
used the same affected mechanism.

## Changes

- Use one common writable `/srv/mobileusb` mount for the web service.
- Keep `/srv/mobileusb/usb.img` read-only inside that service only. Other sandbox
  protections, the unprivileged web account, and atomic `os.replace` are preserved.
- Add an idempotent repair script for existing installations. It changes only a
  systemd drop-in and restarts the website; finish other web transfers first.
- Rebuild the self-contained installer from the corrected source.
- Add Linux mount-namespace regression checks and a release workflow that gates
  publishing on all existing software tests and those checks.

## Existing installations

Download the `mobileusb-fix-web-storage.sh` release asset, copy it to the Pi, and run:

```bash
sudo bash /home/leo/mobileusb-fix-web-storage.sh
```

No reboot, image formatting/repair, USB detachment or full reinstall is needed.
The fix does not apply if the folders actually reside on different filesystems;
the script refuses that layout. Verify upload, delete-to-Trash, and restore through
`http://mobileusb.local:8080` afterwards.

The previously supplied `90-mobileusb-shared-storage.conf` override is equivalent.
If that fix is already applied and functional, no additional device action is
required for this release.

## Installation and safety

`mobileusb-upgrade.sh` is the complete self-contained installer for an existing
MobileUSB setup, not a blank-card installer. Its usual backup and host-ejection
requirements remain. Download checksums are in `SHA256SUMS`.

Two-way conflict handling, ejection-aware synchronization, USB descriptors, and
endpoint-policy behavior are unchanged. This release does not deploy itself to
your Pi. Release tests do not replace live USB/Android/power-loss acceptance tests.
